## Critical path

`DEP-01 owner evidence → WP B3-01 storage decision → WP B3-02 parent/child + WP B3-05 item lifecycle → WP B3-06 atomic publication → WP B3-08 supplier allowlist/RLS → WP B3-07 explicit discovery → WP B3-10 UX integration → WP B3-12 end-to-end evidence`.

Parser/clarification (B3-03/04) and local cache remediation (WP B3-09) can be developed in parallel only after their individual contracts and approvals; they cannot bypass schema, publication or supplier security gates.

## Migration sequencing and safety

No migration has been named or authored. After approval, re-read migration head and create a forward-only additive migration with explicit constraints, indexes, RLS, grants, function patches and reset impacts. Do not edit historical migrations. Preserve existing `requirements` with null parent, all existing RFQs and quotes. Rollback is feature disablement and forward remediation; do not delete published procurement/audit data. Run only on a specifically approved disposable clone using the B3-12 proposal.

## Package-level approval rule

Approval of one package is not approval of dependent database work, external supplier contact, tests/builds, staging or deployment. Each PR/change set should identify exact files, migration, test commands, environment and rollback plan before execution.
